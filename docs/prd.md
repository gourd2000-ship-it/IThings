# 제품 요구사항 정의서 (PRD) - 학교 기자재 관리 시스템 (QR 코드 기반)

본 문서는 Google Apps Script(GAS)와 Google Sheets를 기반으로 하는 학교 기자재 관리 시스템의 요구사항을 정의합니다. 비전문가도 쉽게 유지보수하고 관리할 수 있도록 단순하고 명확하게 설계되었습니다.

---

## 1. 프로젝트 개요

### 1-1. 배경 및 목표
* **배경**: 기존 기자재 관리는 관리자가 직접 모든 교실을 돌며 정보를 확인해야 하므로 시간과 비용이 많이 소요됩니다.
* **목표**: 
  * 기기 사용자가 기기에 부착된 QR코드를 모바일 기기로 스캔하여 정보를 간편하게 확인 및 수정할 수 있는 시스템을 구축합니다.
  * 데이터는 구글 스프레드시트에서 실시간으로 직접 업데이트 및 관리되도록 합니다.
  * 외부 라이브러리 사용을 최소화하고 단일 스크립트(`Code.gs`) 파일 구조로 개발하여 비전문가도 유지보수가 가능하도록 설계합니다.

### 1-2. 전체 서비스 흐름 (Flow)
```text
[기기 라벨 QR코드 스캔]
       ↓
[웹앱 URL 접속 (?id=관리번호)]
       ↓
[GAS: 마스터시트 기기 정보 조회]
       ↓
[모바일 최적화 HTML 웹폼 화면 표시]
       ↓
[사용자가 정보 수정 후 제출]
       ↓
[GAS: LockService를 이용해 마스터시트 해당 행 직접 수정]
       ↓
[저장 완료 화면 및 요약 표시]
```

---

## 2. 시트 및 데이터베이스 구조

본 시스템은 총 3개의 시트로 구성됩니다: `[마스터]`, `[설정]`, `[기기관리라벨]`.
**※ 보안 규정**: 기본적으로 비밀번호(1차), 비밀번호(2차) 등 민감 정보는 화면 표시 및 수정 범위에서 배제됩니다. 다만, 기기의 '종류'가 'PC'이고 [설정] 시트의 'PC민감정보수정허용' 설정값이 'Y'인 경우에 한하여 관리자 허가 하에 IP, 비밀번호(1차), 비밀번호(2차) 항목을 조회 및 수정할 수 있습니다. 라벨 출력 시트에서는 비밀번호 정보가 여전히 완벽히 배제됩니다.

### 2-1. `[마스터]` 시트
실제 기자재 정보가 저장되는 메인 데이터베이스입니다.

| 번호 | 칼럼명 | 데이터 타입 | 용도 및 특징 |
|---|---|---|---|
| 1 | **연번** | 숫자 | 순번 관리용 |
| 2 | **관리번호** | 문자열 | QR URL의 `id` 파라미터와 연결되는 고유 식별자 |
| 3 | **설치장소** | 문자열 | [수정 가능] 기기가 실제 설치된 장소 |
| 4 | **취급자** | 문자열 | [수정 가능] 기기를 사용하는 담당자 또는 책임자 |
| 5 | **종류** | 문자열 | 기기 종류 (예: PC, 노트북, 모니터 등) |
| 6 | **제조사** | 문자열 | 제조사명 |
| 7 | **모델명** | 문자열 | 모델명 |
| 8 | **도입일자** | 날짜/문자열 | 기기 도입 날짜 |
| 9 | **비고** | 문자열 | [수정 가능] 추가 기록 사항 |
| 10 | **IP** | 문자열 | [조건부 수정 가능] PC인 경우 관리자 허가 하에 수정 가능 |
| 11 | **비밀번호(1차)**| 문자열 | [조건부 수정 가능] PC인 경우 관리자 허가 하에 수정 가능 |
| 12 | **비밀번호(2차)**| 문자열 | [조건부 수정 가능] PC인 경우 관리자 허가 하에 수정 가능 |
| 13 | **QR링크** | 문자열 | 웹앱 URL과 관리번호가 결합한 링크 (`웹앱URL?id=관리번호`) |
| 14 | **QR이미지** | 수식/이미지 | 시트 내에서 직접 확인할 수 있는 QR코드 이미지 (`=IMAGE()`) |
| 15 | **최종수정일** | 날짜시간 | 사용자가 웹폼을 통해 마지막으로 수정한 시간 (자동 기록) |

### 2-2. `[설정]` 시트
소스코드를 직접 수정하지 않고 시트 데이터 편집만으로 설정을 제어하기 위한 환경설정 시트입니다.

| 항목 (A열) | 값 (B열) | 설명 |
|---|---|---|
| **기관명** | `비아초등학교` | 라벨 상단 등에 표시될 기관(학교)의 공식 명칭 |
| **웹앱URL** | `https://script.google.com/.../exec` | GAS 배포 후 생성된 실행 URL |
| **설치장소목록** | `교무실,행정실,1-1,1-2,1-3,과학실,컴퓨터실` | 쉼표(,)로 구분된 설치장소 리스트 (웹폼 내 드롭다운 제공) |
| **취급자목록** | `홍길동,김철수,이영희,박민수` | 쉼표(,)로 구분된 취급자 리스트 (웹폼 내 드롭다운 제공) |
| **PC민감정보수정허용**| `Y` 또는 `N` | 종류가 'PC'인 기기의 IP, 비밀번호(1차, 2차) 수정 허용 여부 (기본값: N) |
| **관리자이름** | `교사 이영희` | 라벨지에 일괄 적용될 공통 관리책임자명 (비어 있을 경우 마스터 값 사용) |

### 2-3. `[기기관리라벨]` 시트
구글 스프레드시트 자체 인쇄 기능을 사용하여 A4 용지에 직접 출력하기 위한 기기 라벨 시트입니다. `[마스터]` 시트의 데이터를 바탕으로 배치됩니다.

* **라벨 용지 규격**: **애니라벨 10칸 (2열 5행 구조, 개별 라벨 크기: 88.9mm x 52mm, A4 사이즈)**
* **인쇄 마진 및 배치 세팅**:
  * **상단 마진**: `18.5mm` (스프레드시트 1행 높이를 `70px`로 조정하여 여백 확보)
  * **좌측 마진**: `15.5mm` (스프레드시트 A열 너비를 `58px`로 조정하여 여백 확보)
  * **열 간격 (가로 갭)**: `1.2mm` (스프레드시트 H열 너비를 `5px`로 설정)
  * **행 간격 (세로 갭)**: `0mm` (라벨 간 경계가 맞닿아 있어 세로 간격행은 생략하고 연속 배치)
* **라벨 양식 내 안전 여백 (Safe Margin / Padding)**:
  * **목적**: 실제 인쇄 시 1~2mm 정도 발생하는 프린터 급지 오차로 인해 글자나 QR코드가 잘려 나가는 것을 방지합니다.
  * **설계**: 개별 라벨 크기(88.9mm x 52.0mm = 336px x 197px) 사방에 **상하좌우 12px(약 3mm)**의 안전 여백을 둡니다.
  * **구조**: 
    * 가로(336px): 좌측여백(12px) | 항목명(80px) | 직위(48px) | 이름(96px) | QR코드(88px) | 우측여백(12px)
    * 세로(197px): 상단여백(12px) | 기관명(28px) | 종류(35px) | 관리번호(37px) | 관리책임자(37px) | 취급자(36px) | 하단여백(12px)
  * **디자인**: 바깥 경계는 옅은 회색 실선으로 칠하고, 안전 여백 안쪽의 실데이터 영역(C~F열 및 r+1~r+5행)만 짙은 회색 실선 테두리를 작성하여 데이터 영역을 칼선으로부터 분리합니다.
* **출력 방식**: 구글 스프레드시트에서 제공하는 시트 인쇄(출력) 인터페이스를 사용하여 별도의 외부 프로그램 없이 직접 출력합니다.
* **라벨 카드 인쇄 항목 (첨부 이미지 기준)**:
  1. **기관명** (상단 타이틀, 예: `비아초등학교` - `[설정]` 시트에서 로드)
  2. **종류** (예: `PC`)
  3. **관리 번호**
  4. **관리책임자** (직위 + 이름 형식 분할 표시, 예: `교사` / `이영희`)
  5. **취급자** (직위 + 이름 형식 분할 표시, 예: `교사` / `홍길동`)
  6. **QR코드** (우측 영역 배치, '관리 번호', '관리책임자', '취급자' 3개 행 높이로 병합하여 표시)
* **주의**: 비밀번호 관련 칼럼 및 정보는 라벨에 절대 표시하지 않습니다.

## 3. 웹 애플리케이션 (UI/UX) 요구사항

스마트폰 카메라로 QR코드를 스캔하여 바로 접근하는 시나리오이므로, **모바일 화면에 최적화(Responsive, Mobile-first)**된 직관적이고 미려한 디자인을 적용합니다.

### 3-1. 화면 구성 상세
1. **타이틀 바**:
   * 제목: `"기자재 정보 확인 및 수정"`
   * 깔끔하고 현대적인 헤더 디자인
2. **기기 기본 정보 영역 (조회 전용)**:
   * 표시 항목: 관리번호, 종류, 제조사, 모델명, 도입일자
   * 스타일: 읽기 전용임을 직관적으로 알 수 있도록 비활성화 스타일 또는 텍스트 카드 형태로 표시
3. **수정 입력 영역 (사용자 입력)**:
   * **설치장소**: `[설정]` 시트의 '설치장소목록' 값을 기반으로 한 드롭다운 선택 상자 (Select Box)
   * **취급자**: `[설정]` 시트의 '취급자목록' 값을 기반으로 한 드롭다운 선택 상자 (Select Box)
   * **비고**: 자유롭게 기재할 수 있는 여러 줄 입력창 (Textarea)
   * **조건부 노출 항목 (IP, 비밀번호 1차, 비밀번호 2차)**: 기기 종류가 'PC'이고 설정 시트의 'PC민감정보수정허용' 값이 'Y'인 경우 화면에 수정 폼으로 노출됩니다.
     * **IP**: 일반 텍스트 입력창 (현재 시트의 값 표시)
     * **비밀번호(1차)**: 패스워드 입력창 (안전을 위한 비밀번호 마스킹)
     * **비밀번호(2차)**: 패스워드 입력창 (안전을 위한 비밀번호 마스킹)
   * *참고*: 추후 유지보수 과정에서 `종류`, `제조사`, `모델명`, `도입일자`도 수정 가능하도록 변경하기 쉽게 코드를 확장성 있게 작성할 것.
4. **저장 버튼**:
   * 버튼명: `"수정 내용 저장"`
   * 클릭 시 로딩 애니메이션(Spinner) 등을 노출하여 중복 클릭 방지 및 데이터 처리 중임을 표시
5. **저장 후 완료 화면**:
   * 메시지: `"저장되었습니다."`
   * 사용자가 방금 수정한 내용을 요약하여 카드로 다시 보여줌
   * 필요한 경우 추가 수정을 할 수 있는 `"다시 수정하기"` 버튼 제공
6. **예외/오류 화면**:
   * 파라미터 누락 (`id` 없음): `"관리번호가 전달되지 않았습니다."`
   * 기기 조회 실패 (매칭되는 관리번호 없음): `"해당 관리번호의 기기를 찾을 수 없습니다."`
   * 제출 처리 중 에러 발생: `"저장 중 오류가 발생했습니다."`

## 4. 시스템 설계 및 API 함수 스펙

모든 코드는 단일 파일인 `Code.gs`로 구성하며, 클라이언트용 HTML/CSS/JS 역시 문자열 템플릿 형태로 내장하여 배포 관리가 극도로 편리하게 만듭니다.

### 4-1. 주요 함수 명세 (`Code.gs`)

* **`doGet(e)`**
  * **설명**: 웹앱 최초 진입점.
  * **역할**:
    1. URL 쿼리 파라미터 `e.parameter.id`를 추출합니다.
    2. `id`가 없는 경우 `createErrorHtml_("관리번호가 전달되지 않았습니다.")`를 호출합니다.
    3. `id`가 있는 경우 마스터 시트에서 기기를 매칭하고, `getSettings_()`로 옵션을 가져옵니다.
    4. 기기가 없으면 `createErrorHtml_("해당 관리번호의 기기를 찾을 수 없습니다.")`를 반환합니다.
    5. 기기와 설정이 조회되면 `createHtml_(device, settings)`를 호출하여 정상 수정 폼을 클라이언트에 반환합니다.

* **`getSettings_()`**
  * **설명**: `[설정]` 시트의 설정을 읽어옵니다.
  * **반환 형식**: `{ webAppUrl: String, locations: String[], managers: String[], pcSensitiveEditAllowed: Boolean }`
  * **역할**: 설정 시트의 키-값 쌍을 매핑하고, 목록 값은 쉼표(`,`) 단위로 쪼개어 배열로 변환합니다. `PC민감정보수정허용` 값('Y'인 경우 `true`, 그 외 `false`)도 함께 포함합니다.

* **`getDeviceById_(id)`**
  * **설명**: 관리번호를 기반으로 기기 정보를 조회합니다.
  * **반환 형식**: `{ rowNum: Number, data: Object }` (해당 행 번호 포함)
  * **역할**: 마스터 시트의 헤더명을 매핑하여 `관리번호` 열에서 파라미터 `id`를 검색합니다. 기본적으로 비밀번호 관련 열은 조회에서 배제하되, 기기가 'PC'이고 설정에서 허용된 경우에는 IP와 비밀번호(1차, 2차)도 포함하여 반환합니다.

* **`updateDevice_(id, formData)`**
  * **설명**: 사용자가 폼에 입력한 데이터로 마스터 시트를 수정합니다.
  * **역할**:
    1. `LockService.getScriptLock()`을 활용해 데이터 경쟁 문제를 예방합니다. (대기 시간 10초 설정)
    2. `getDeviceById_(id)`를 호출하여 대상 행의 번호를 확인합니다.
    3. 해당 행의 '설치장소', '취급자', '비고' 열에 해당하는 값을 업데이트하고, '최종수정일' 열에 현재 일시(`new Date()`)를 기록합니다.
    4. 기기가 'PC'이고 관리자 설정으로 민감정보 수정이 허용된 경우, 'IP', '비밀번호(1차)', '비밀번호(2차)' 열의 값도 폼 데이터에 따라 함께 업데이트합니다.
    5. 수정 로그가 별도로 필요한 경우를 대비해 확장 포인트를 확보해 둡니다.
    6. 잠금을 해제합니다.
  * **주의**: 허가되지 않은 일반 상황 또는 PC가 아닌 기기일 경우 비밀번호 관련 데이터는 절대 수정하거나 저장하지 않습니다.

* **`createHtml_(device, settings)`**
  * **설명**: 렌더링할 모바일 웹 화면의 HTML/CSS/JS 문자열을 생성합니다.
  * **역할**: HTML5 표준 준수, 뷰포트 메타 태그 적용, 현대적인 HSL 테마 디자인, 그리고 `google.script.run`을 사용한 `updateDevice_` 비동기 호출 코드를 구성합니다.

* **`createErrorHtml_(message)`**
  * **설명**: 비정상적인 접근 또는 에러 시 표시할 오류 화면을 반환합니다.

* **`setupSheets()`**
  * **설명**: 시스템 초기 설정을 수행하는 관리자용 함수입니다.
  * **역할**: `[마스터]`, `[설정]`, `[기기관리라벨]` 시트가 존재하지 않는 경우 자동으로 생성하고 초기 템플릿(헤더 및 설정 기본값)을 주입합니다.

* **`refreshQrLinks()`**
  * **설명**: 설정 시트의 웹앱URL과 마스터 시트의 관리번호를 이용하여 QR링크와 이미지 수식을 갱신합니다.
  * **역할**: `[마스터]` 시트 전체를 순회하며 `[웹앱URL]?id=[관리번호]` 형태의 링크를 작성하고, `IMAGE("https://chart.googleapis.com/chart?chs=150x150&cht=qr&chl=" + QR링크)` 형태의 수식을 입력합니다.

* **`createLabelSheet()`**
  * **설명**: 출력용 라벨 시트를 생성하거나 재생성합니다.
  * **역할**: `[마스터]` 시트의 각 행 데이터를 읽어서 바둑판 배열이나 리스트 형태로 라벨 인쇄 서식에 맞게 `[기기관리라벨]` 시트를 구성합니다.

## 5. 비기능적 요구사항 (보안 및 안정성)

* **보안성**:
  * 사용자 비밀번호 관련 변수나 로직은 배제하며, 오직 설정에 지정된 시트 데이터와 전달받은 `id` 식별값에만 의존합니다.
  * 사용자가 입력한 데이터는 시트에 입력될 때 단순 문자열 데이터로 안전하게 처리되어 스크립트 인젝션을 방지합니다.
* **동시성 제어**:
  * 여러 사용자가 동시에 동일 기기 혹은 다른 기기를 수정하여 제출할 수 있으므로, 스프레드시트 업데이트 함수(`updateDevice_`) 시작 지점에 `LockService`를 설정하여 쓰기 충돌을 방지합니다.
* **유지보수성**:
  * 열의 위치가 변경되거나 추가되더라도 깨지지 않도록 하드코딩된 열 인덱스(예: `1`, `2`) 대신 **헤더 행의 값을 기반으로 동적으로 인덱스를 매핑**하여 사용하도록 작성합니다.
  * 모든 함수에 직관적인 한국어 주석과 동작 설명을 포함합니다.

## 6. 인수인계 및 운영 절차 안내

1. **스프레드시트 복사**: 
   * 인수인계 시 대상자는 구글 드라이브 상에서 해당 스프레드시트를 "사본 만들기"로 복제합니다. (이때 내장된 Apps Script 프로젝트도 함께 복사됩니다.)
2. **Apps Script 연결 및 최초 초기화**:
   * 복사된 스프레드시트의 `확장 프로그램` > `Apps Script`를 클릭해 편집기를 엽니다.
   * `Code.gs` 내 `setupSheets()` 함수를 선택하여 실행(최초 1회)하여 시트 구조를 바르게 초기화하고 권한 승인을 완료합니다.
3. **웹앱 배포**:
   * Apps Script 우측 상단 `배포` > `새 배포` 선택.
   * 유형: `웹앱`, 설명: `기자재 관리 시스템 v1.0`
   * 액세스 권한이 있는 사용자: `모든 사용자` (로그인 없이 누구나 스캔하여 제출할 수 있도록 설정)
   * 배포 후 제공되는 **웹앱 URL**을 복사합니다.
4. **설정 업데이트**:
   * 복사한 웹앱 URL을 `[설정]` 시트의 `웹앱URL` 값에 붙여넣습니다.
5. **QR 링크 갱신**:
   * Apps Script에서 `refreshQrLinks()` 함수를 호출하여 마스터 시트 내의 QR링크와 QR코드를 전체 자동 갱신합니다.
6. **라벨 재출력 (구글 시트로 직접 인쇄)**:
   * Apps Script에서 `createLabelSheet()`를 실행하여 새로 변경된 QR코드가 들어간 라벨을 `[기기관리라벨]` 시트에 생성합니다.
   * 생성 완료 후, 구글 스프레드시트의 인쇄 기능(단축키: `Ctrl + P`)을 활용하여 출력합니다. 인쇄 서식은 **애니라벨 10칸 (88.9mm x 52mm)** 규격에 맞춰 구글 시트 안에서 바로 배치되어 출력됩니다. 용지 인쇄 설정에서 배율을 '페이지 너비에 맞춤' 혹은 '100%'로 조정한 뒤, 라벨 스티커 용지에 인쇄하여 각 기기에 부착합니다.
