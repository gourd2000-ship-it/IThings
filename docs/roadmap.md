# 학교 기자재 관리 시스템 (QR 코드 기반) 개발 로드맵

Google Apps Script(GAS)와 Google Sheets를 기반으로 비전문가도 쉽게 유지보수할 수 있는 모바일 최적화 학교 기자재 관리 시스템의 성공적인 개발을 위한 로드맵입니다.

## 개요
학교 기자재 관리 시스템은 사용자가 기기에 부착된 QR 코드를 모바일로 스캔하여 기자재 정보를 간편하게 확인하고 수정할 수 있는 기능을 제공하며, 데이터는 구글 스프레드시트에서 실시간으로 직접 업데이트 및 관리됩니다.
- **마스터 시트 기반 정보 관리**: 고유한 관리번호로 매핑된 기기 정보의 실시간 확인 및 안전한 수정
- **모바일 최적화 웹앱**: 스마트폰 카메라 스캔으로 빠르게 접속하고 쉽게 데이터를 입력할 수 있는 모바일 반응형 UI
- **인쇄용 라벨 자동 구성**: 관리번호, QR코드, 기본 정보가 포함된 인쇄용 라벨 시트 생성
- **비전문가 유지보수 지향**: 단일 스크립트(`Code.gs`) 구조와 시트 데이터 기반 환경설정

## 개발 워크플로우
1. **작업 계획**
   - 기존 코드베이스를 학습하고 현재 상태를 파악합니다.
   - 새로운 작업을 포함하도록 `ROADMAP.md`를 업데이트합니다.
   - 우선순위 작업은 마지막 완료된 작업 다음에 삽입합니다.

2. **작업 생성**
   - 기존 코드베이스를 학습하고 현재 상태를 파악합니다.
   - `/tasks` 디렉토리에 새 작업 파일을 생성합니다.
   - 명명 형식: `XXX-description.md` (예: `001-setup.md`)
   - 고수준 명세서, 관련 파일, 수락 기준, 구현 단계를 포함합니다.
   - API/비즈니스 로직 작업 시 "## 테스트 체크리스트" 섹션을 필수로 포함하여 Playwright MCP 테스트 시나리오를 작성합니다.
   - 예시를 위해 `/tasks` 디렉토리의 마지막 완료된 작업을 참조합니다.

3. **작업 구현**
   - 작업 파일의 명세서를 따릅니다.
   - 기능과 기능성을 구현합니다.
   - API 연동 및 비즈니스 로직 구현 시 Playwright MCP로 테스트를 필수로 수행합니다.
   - 각 단계 후 작업 파일 내 단계 진행 상황을 업데이트합니다.
   - 구현 완료 후 Playwright MCP를 사용한 E2E 테스트를 실행하여 검증합니다.
   - 테스트 통과 확인 후 다음 단계로 진행합니다.
   - 각 단계 완료 후 중단하고 추가 지시를 기다립니다.

4. **로드맵 업데이트**
   - 로드맵에서 완료된 작업을 ✅로 표시합니다.

## 개발 단계

### Phase 1: 애플리케이션 골격 구축
- **Task 001: 프로젝트 구조 및 단일 Code.gs 골격 설정** - 우선순위
  - 프로젝트 루트 및 기본 디렉토리 설정
  - 단일 스크립트 파일인 `Code.gs` 생성 및 기본 전역 변수 설정
  - HTML 템플릿 반환을 위한 UI 골격 및 테스트 핸들러 작성
  - 로컬 환경과 GAS 환경 개발을 보조하는 디렉토리 구성
  
- **Task 002: 타입 정의 및 데이터 스키마 설계**
  - 마스터 시트(IP, 비밀번호 1차, 비밀번호 2차 칼럼 포함), 설정 시트(PC민감정보수정허용 포함), 기기관리라벨 시트의 칼럼 정의 JSDoc/TypeScript 타입 파일 생성
  - API 통신 시 사용할 `Device` (조건부 민감 정보 필드 포함), `Settings` (pcSensitiveEditAllowed 포함), `UpdateResult` 등의 인터페이스 정의
  - 시트 헤더 매핑 상수 및 열 인덱스 동적 탐색 구조 설계

### Phase 2: UI/UX 완성 (더미 데이터 활용)
- **Task 003: 모바일 최적화 공통 UI 컴포넌트 구현**
  - 외부 라이브러리를 배제한 바닐라 CSS(Vanilla CSS) 기반 HSL 색상 테마 및 모바일 친화적 뷰포트 설정
  - 공통 레이아웃 컴포넌트(타이틀 바, 비활성 텍스트 카드, 드롭다운 Select Box, Textarea) 구현
  - 민감 정보 입력을 위한 IP 일반 텍스트 입력창 및 패스워드 마스킹 입력창 컴포넌트 구현
  - 클릭 시 로딩 스피너 및 중복 방지 제어 로직 구현
  
- **Task 004: 전체 모바일 웹폼 및 예외 화면 UI 구현**
  - 기기 상세 정보 표시 및 수정 폼 UI 구축 (더미 데이터를 활용하여 렌더링)
  - 기기 종류가 'PC'이고 설정이 허용된 경우 IP 및 마스킹된 비밀번호 입력폼을 노출하는 조건부 UI 노출 로직 구현 (더미 설정 기반)
  - 저장 처리 및 저장 완료 후 결과 요약 카드 화면 구현
  - 예외 상황별 오류 화면 UI 구축 (관리번호 누락, 조회 실패, 제출 에러 등)

### Phase 3: 핵심 기능 구현 (시트 관리 및 데이터 연동 API)
- **Task 005: 마스터 및 설정 시트 자동 초기화 기능 구현 (setupSheets)** - 우선순위
  - `[마스터]`(IP, 비밀번호 1차/2차 헤더 포함) 및 `[설정]`(PC민감정보수정허용 기본값 N 포함) 시트 부재 시 시트 자동 생성 및 헤더 주입 함수 `setupSheets()` 구현
  - `[설정]` 시트의 설치장소목록, 취급자목록 및 `PC민감정보수정허용` 값(Y일 때 true, 그 외 false)을 파싱하여 반환하는 `getSettings_()` 도우미 함수 개발
  
- **Task 006: QR 링크 및 이미지 갱신 기능 구현 (refreshQrLinks)**
  - `[마스터]` 시트를 순회하며 `[웹앱URL]?id=[관리번호]` 형태의 링크 문자열 생성 로직 구현
  - Google Chart API(또는 대체 QR API)를 사용하여 `=IMAGE()` 수식 형태로 마스터 시트의 QR이미지 열을 채우는 `refreshQrLinks()` 함수 구현
  
- **Task 007: 애니라벨 10칸 규격(88.9mm x 52mm) 출력용 시트 서식 적용 및 생성 구현 (createLabelSheet)**
  - `[마스터]` 시트 데이터를 읽고 비밀번호 정보를 필터링하여 안전한 기기 정보 리스트 추출 (PC 민감 정보 수정 허용 여부와 무관하게 비밀번호 정보는 라벨에서 완벽히 배제)
  - 첨부 이미지 레이아웃에 따라 **기관명(예: 비아초등학교)**, **종류**, **관리 번호**, **관리책임자(직위+이름 분할)**, **취급자(직위+이름 분할)**, **QR코드(우측 정렬)**를 배치하고, **애니라벨 10칸(A4 용지, 2열 5행 구조, 개별 라벨 88.9mm x 52mm) 규격**에 적합하게 `[기기관리라벨]` 시트의 격자를 세팅하는 `createLabelSheet()` 함수 개발
  - 프린트 오차 및 잘림 방지를 위해 **상하좌우 마진 세팅(상단 여백 18.5mm, 좌측 여백 15.5mm, 가로 갭 1.2mm, 세로 갭 0mm)** 및 **라벨 개별 카드 내의 상하좌우 안전 여백(각 12px ≈ 3mm 패딩 열/행 적용)**을 격자 크기에 수식/상수로 자동 적용하도록 구현
  - 설정 시트의 `관리자이름` 설정 시 마스터의 개별값 대신 공통 설정 이름을 라벨의 '관리책임자' 항목에 일괄 대입하는 오버라이드 로직 결합
  - 구글 스프레드시트 자체 인쇄 기능(Ctrl + P)을 사용하여 A4 라벨 용지에 정확하게 정렬 및 인쇄할 수 있도록 행 높이와 열 너비를 정비하고 오차 안전 구역을 반영하는 단계 포함
  
- **Task 008: 기기 정보 조회 및 수정 처리 API 구현 (getDeviceById_, updateDevice_)**
  - 전달받은 `id` 값을 `[마스터]` 시트의 관리번호 열에서 동적으로 탐색하고 기기 데이터를 조회하는 `getDeviceById_(id)` 함수 구현
    - 기본적으로 비밀번호 관련 열은 제외하되, 기기 종류가 'PC'이고 설정에서 민감정보 수정이 허용된(`pcSensitiveEditAllowed`가 true) 경우에 한해 IP와 비밀번호(1차, 2차)를 포함하여 반환하도록 조건부 조회 로직 구현
  - `LockService.getScriptLock()`을 활용하여 쓰기 충돌을 방지(대기 시간 10초)하는 `updateDevice_(id, formData)` 함수 구현
    - 기본 수정 칼럼(설치장소, 취급자, 비고, 최종수정일) 외에, 기기가 'PC'이고 설정이 허용된 경우에만 'IP', '비밀번호(1차)', '비밀번호(2차)' 열을 조건부 업데이트하는 방어적 로직 구현
  
- **Task 009: 웹앱 진입점(doGet) 및 HTML 렌더러 구현**
  - URL 파라미터 `e.parameter.id`를 검증하고 예외 화면 또는 정상 수정 폼을 분기 처리하는 `doGet(e)` 구현
  - 정상 조회 시 `createHtml_()`, 에러 발생 시 `createErrorHtml_()`을 호출하여 최종 HTML 파일 반환
  
- **Task 010: 클라이언트-서버 연동 및 통합 테스트**
  - 모바일 웹폼에서 `google.script.run`을 사용해 `updateDevice_` 함수를 비동기 호출하는 API 바인딩 구현
  - 저장 결과에 따른 클라이언트 상태 업데이트 및 완료 화면 표시 로직 구현
  - Playwright MCP를 활용하여 정상 사용자 플로우, 조건부 민감 정보(PC 기기 및 권한 Y/N 상황) 노출 및 저장, 엣지 케이스(id 미전달, 조회 실패, 에러 등)에 대한 통합 테스트 시나리오 작성 및 수행

### Phase 4: 고급 기능 및 최적화
- **Task 011: 동적 헤더 탐색 및 보안/안정성 최적화**
  - 마스터 시트 내의 열 순서가 변경되거나 칼럼이 추가되어도 시스템이 깨지지 않도록 헤더명을 동적으로 분석하여 칼럼 인덱스를 매핑하는 로직 검증 및 보완
  - HTML 인젝션 방지 및 시트 입력 문자열의 안전성(Sanitizing) 강화
  
- **Task 012: 배포 가이드라인 및 운영 매뉴얼 작성**
  - 복사본 제작, 최초 `setupSheets` 권한 승인, 웹앱 배포, URL 설정, QR링크 갱신, 라벨 인쇄로 이어지는 단계별 운영 매뉴얼 작성
